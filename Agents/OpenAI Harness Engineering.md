### 第一集： https://v.douyin.com/Y_3xjYL5q-w/

一、Harness Engineering 概念提出
 
- OpenAI 提出“Harness Engineering”，其核心是工程师不再写代码，而是为 Agent 搭建工作环境。
- OpenAI 团队做过实验：5 个月构建一个真实上线、拥有百万行代码的复杂系统，人类工程师 0 行手写代码，期间合并约 1500 个 PR。最初 3 名工程师驱动 Codex，后扩展到 7 人，人均吞吐反而提升，实现“人类掌舵，Agent 执行”。
 
二、Harness Engineering 提出的背景
 
- Agent 写不出好代码，瓶颈不在模型，而是因为它“瞎”——缺乏工具、系统架构认知和上下文，是工程结构没搭好。
- Harness Engineering 就是为解决此问题而生，它是构建一个系统，让 AI 可以稳定、可控、可验证地工作。当 Agent 犯错时，工程师要思考“环境里缺了什么信息导致错误”，而非直接修代码。
 
三、工程师角色转变
 
- 传统软件工程中，工程师是“泥瓦匠”，关心每一行代码语法；在 Harness Engineering 里，工程师变成系统设计师，不再直接写代码。代码从昂贵资产变成廉价编译产物，可随时生成和丢弃。
 
四、Harness 工程师的三大核心职责
 
1. 设计环境：搭好脚手架，包括仓库结构、CI 流水线、Lint 规则、开发者工具等，这些是 Agent 赖以生存的基础设施。
2. 明确意图：用清晰语言拆解需求，转化为 Agent 能理解的无歧义规范，而非模糊要求。
3. 构建反馈：建立自我审查、静态检查、集成测试的闭环，让 Agent 在提交代码前在闭环里自己跑通，这是反馈闭环工程，而非提示词工程。
 
五、日常工作流与核心总结
 
- 工作方式：深度优先：把大目标拆解成设计、编码、审查、测试等小模块，让 Agent 逐个完成，再解锁更复杂任务。失败时，不是“再试一次”，而是回到元问题“缺了什么能力，如何让能力对 Agent 清晰可执行”。
- 交互方式：人类工程师几乎完全通过 Prompt 与系统交互，描述任务启动 Agent，Agent 会自己开 Pull Request，然后在本地自我审查、请求其他 Agent 审查，根据反馈自动修改，循环往复直到所有 Agent 审查者满意。这个流程使用团队标准开发工具（如 gh 命令行、本地脚本等），无需人类在命令行复制粘贴，此流程被称为“Ralph Wiggum Loop”。
- 核心总结：当代码可被无限生成，工程师的价值从“写代码”迁移到“设计让代码产生的环境”，Harness Engineering 重要性凸显。

### 第二集：

这是一期关于“慢学AI·精读系列”的视频，内容围绕OpenAI的工程博客《Harness Engineering: leveraging Codex in an agent-first world》展开，聚焦当代代码吞吐量爆炸下验证成为瓶颈的问题及OpenAI的解决方法。
 
核心问题与背景
 
当代代码生成速度不再是瓶颈，验证能力成为新瓶颈。以前的AI Agent只能“写”代码，写完后无法查看页面渲染结果、不知系统是否报错、性能是否变差，需要人类验证后截图告知问题。而OpenAI的解法是让Agent自己验证自己，这需要一个前提——Agent得先“看得见”系统的状态。
 
关键概念：Legibility（可读性）
 
这里的可读性不是指“代码写得好不好读”，而是系统的状态对Agent来说是否透明、可解析、可验证。这带来思维转变：不要问Agent能为你做什么，而要问你能为Agent提供什么。
 
OpenAI的具体做法
 
1. 独立工作空间 - Git Worktree
从主代码库复制一份独立副本，Agent在这个副本里自由折腾，修改不影响他人，如同每个厨师有独立操作台。
2. 给Agent装“眼睛”
- 接入Chrome DevTools Protocol，让Agent能像人类按F12打开开发者工具那样，检查页面结构、网络请求、调试代码。
- 为Agent创建处理DOM快照、截图和页面导航的专门“技能”。DOM快照如同网页的“X光片”，记录网页底层树状结构（DOM）在某一刻的状态，供Agent分析，使其能直接复现Bug、验证修复结果并推理UI行为。
3. 给Agent装“听诊器”
构建临时可观测性环境，每个Agent任务有独立的日志、指标，用完即毁，避免并行任务信息干扰。Agent可通过LogQL查询日志（如在海量日志中精确搜索错误记录），通过PromQL查询性能数据（如最近五分钟的平均响应时间）。这使得“确保服务启动在800毫秒内完成”等原本需人类盯着监控面板的约束，现在Agent可自主验证。
 
最终效果
 
Agent从“需要人盯着才能干活”，变成“可以自主干活值夜班”。单次Codex运行在一个任务上可工作超过六小时（通常在人类睡觉时间），实现写代码→看效果→查日志→发现问题→修复→再验证的闭环，完全无需人类介入，可自动运行。
 
总结与下期预告
 
本期讲“状态可读”——让Agent能看见UI、得知系统内部状态，从而实现闭环自主工作。下期将讲解如何让“知识被Agent发现”。
