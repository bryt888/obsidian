作者： 技术爬爬虾
 
Token消耗降低十倍。
这套流程可以让AI自动操作浏览器，代替你完成一切机械重复性的工作，而且特别的省TOKEN。很多工作流甚至全程不需要AI参与，0TOKEN就能把自动化任务跑起来。比如可以0TOKEN抓取电商网站评论，导出成CSV文件，自动把Markdown文章发布到X。还有对自己开发的Web APP进行AI自动化测试。
我们并不需要懂浏览器的相关知识，只用自然语言就能完成这些任务。本期视频我们使用的Agent框架是Claude Code或者Codex，浏览器自动化方案是Playwright CLI搭配配套的Skill。Playwright CLI是26年初微软开源的全新浏览器自动化工具。
根据官方的基准测试，playwright CLI比起传统的playwright MCP方案差不多能够减少4倍的TOKEN消耗。工具搭建好以后，我们可以把很多固定的工作流程沉淀成skills，让AI能够又快又省的完成任务。甚至熟练后你会发现很多固定流程甚至不需要AI参与，只需要让AI编写好一个固定的脚本就可以0TOKEN全自动完成工作。
废话不多说，我们直接开始。
· 在开始之前，我们需要先确保电脑上安装了nodejs。如果没有安装过，可以来到nodejs的官网，根据自己的操作系统下载对应的安装包。
· 然后我们打开一个命令行终端，输入 npm install -g @playwright/cli@latest 命令安装playwright CLI，安装完成。
· 下一步我们要确保电脑上安装了Chrome浏览器，如果是edge浏览器也可以，不过最好还是推荐使用Chrome。
这样准备工作就完成了。我们来测试一下，我们可以使用 playwright-cli open google.com --headed 命令，使用Playwright CLI操作Chrome浏览器。
· 打开谷歌的官网，最后一个参数 --headed 表示使用的是有头浏览器。如果不加这个参数，Playwright默认使用的是无头浏览器。无头浏览器会在后台静默运行，虽然比较省内存，但是我们看不到浏览器的页面。所以为了方便调试一般加上这个参数，回车。
playwright CLI自动操作Chrome打开了谷歌网页，在控制台这边可以看到playwright CLI只是输出了一个简洁的网页摘要，而没有返回整个网页的全部DOM结构，下面附带了一个网页结构的文件地址。
AI Agent如果需要更详细的网页结构信息就可以选择读取这个快照文件获取更详细的信息，如果不需要就可以选择不读取。这也就是为什么Playwright CLI比起MCP更节省上下文的秘密所在。因为MCP是把网页内容全部塞进上下文，而Playwright CLI可以由AI按需读取。
同样 playwright-cli screenshot 命令也体现了按需加载的思路，Screenshot是给浏览器截图，看到截屏的时候它还是以一个PNG的文件的形式存放在了电脑的本地磁盘上，由AI决定是否来读取，而不是像MCP那样直接把图片塞入AI的上下文。
再介绍一个重要的参数就是 --persistent ， persistent 表示把cookie、登录状态、本地存储之类的数据写到磁盘里面，下次使用的时候继续拿出来用，这样就不需要每次都重新登录了。比如这里执行 playwright-cli open google.com --headed --persistent ，因为之前登录过，打开的谷歌首页就变成了已经登录过的状态了。
到这里就介绍完了playwright CLI的基础使用，下一步就把它接入AI Agent。本期视频主要使用的Agent框架是Claude code和Codex，这里就不赘述了。
playwright CLI是一个新诞生的命令行工具，AI并不知道该如何使用这些命令，所以需要给AI搭配skills来一起使用。Playwright CLI作为技术底座，而skills作为说明文档，CLI加skills搭配起来使用就可以取代传统的MCP方式，这也是最近的一个技术发展趋势。先新建一个项目文件夹，打开这个文件夹，打开命令行终端，输入 playwright-sli install --skill 命令，给文件夹里面安装skills，这样skills就安装完成了。
它放到了新建的项目文件夹的 .claude 目录下面，然后就可以启动Claude Code，输入“你有哪些skills”，它可以成功的读取到playwright CLI技能，这样就成功的把它接入了Claude code。
· 接下来来看另外一个Agent的框架，就是Codex，只需要在项目目录里面把存放skills文件夹的名字从 .claude 改成 .codex ，来适配Codex就完成了。
· 然后还是在这个目录里面打开Codex，在Codex里面输入 /skills 命令，看到这里列出了playwright CLI，在Codex里面也配置完成了。
· 在Codex里面测试一下基础用法，输入“用playwright-cli参数--headed --persistent，打开Grok，问问今天青岛的天气怎么样”，AI成功的打开了浏览器，来到了Grok的首页，帮我们自动输入了问题，自动点击了回车，拿到了结果，最终成功打印到了控制台上，任务就完成了。
· 来看一个复杂一些的例子，输入“用playwright-cli带参数--headed --persistent查看https://detail.tmall.com/item.htm?abbucket=4&id=612098145454&mi_id=0000000000000000000&skuId=5872701131&xxc=taobaoSearch，保存到一个CSV文件里面，查看这个商品前100条评论，然后保存到一个CSV文件里面”。然后让AI把评论的全过程还有遇到的坑都提炼出来保存到skills里面，后面只要让它保存评论就能调用这个skill完成任务。
AI帮我们创建了skill，把任务里面可以复用的内容都固化进了知识。这里让它修改一下，把skill放到项目目录里面，skill成功放到了项目目录下面的 .codex/skills 里。现在有两个skill了，一个是playwright CLI，还有一个就是刚才保存评论流程的skill。
这里先清理一下上下文，再用相同的任务来测试一下。有了skills的指导以后效果就不一样了，AI充分吸取了之前的经验，没有再出现多余的动作，也没有报错，用最低的token消耗完美的完成了任务。
第一次让AI自己摸索，自己试错，用了41%的上下文才完成了任务。第二次有了skills的指导，只用了5%的上下文就完成了任务。通过把过程提炼总结成skills，获得了将近十倍的效率提升。
抓取评论是一个固定流程，其实并不需要AI进行智能化的控制，可以直接把它编写成一个固定的脚本。这里输入提示词“把刚才所有的playwright-cli命令汇总成一个脚本，执行脚本就能获取商品的前100条评论，并且保存到一个CSV文件里面。注意每一步都要有合理的延时与等待，确保任务成功”。
脚本写完先测试一轮，很快Codex为我们编写完成了脚本，它已经自己测试通过了。来看一下脚本长什么样，在Windows电脑上就是一个PowerShell脚本。AI以编程的方式把刚才的步骤都固定下来了，比如第一步打开商品页面，第二步确认浏览器里打开的是正确的URL，第四步点击查看全部评价按钮，最后一步把JSON数据保存成CSV文件。
也来测试一下，打开一个命令行终端，输入PowerShell脚本的路径，回车执行。这是一个固定的流程，中间没有AI的参与。看到这次不再依赖Codex了，直接执行PowerShell脚本0 Token零成本就完成了任务，还取得了相同的效果。
总结一下这套浏览器自动化的流程。
· 准备阶段：先安装Node.js、playwright CLI还有Chrome浏览器。
· 第二步：选择喜爱的AI Agent工具，把playwright CLI的skill安装进去。
· 第三步：给AI一个复杂的任务，让它自己摸索并且执行完。
· 第四步：让AI把刚才的执行结果提炼总结成skill，之前遇到的坑就不要再踩了。
· 第五步：重试相同的任务，AI在skills的指导下可以把Token的消耗降低十倍。
· 第六步（可选）：如果是完全固定化的流程，让AI把这个过程直接编写成一个脚本，有了脚本以后甚至可以直接执行脚本完成任务，完全不需要AI参与，把Token消耗直接降低到0。
再来看一个实战案例，最近把自己的视频用AI转成图文教程，然后发到各个平台上面。大部分平台发文章都比较简单，唯独有一个平台X发文章的步骤非常的繁琐。
这是一篇Markdown格式的文章，不能直接以Markdown格式粘贴到X平台。首先格式会错乱，第二个问题是图片都展示不出来。然后测试如果使用HTML格式是可以粘贴的，但又出现新问题，图片粘贴不过来，都变成了照相机小符号，只能手动删除小符号再一张张粘贴图片，非常麻烦。
接下来就使用前面介绍的自动化流程，把发文章的全过程进行AI自动化。这里使用Codex编写一个Python脚本，把文章里的图片下载到本地，从001开始编号放到 images 文件夹里面，先转换成只使用本地图片的Markdown文章，然后运行脚本把本地图片的Markdown文章转换成HTML格式。注意HTML格式里面每张图都应该是独立段落。
AI帮我们编写好了脚本并且为我们转换好了文章。图片都放到了 images 文件夹下面，文章也转换成了HTML格式。
· 下一步让AI帮我们自动发文，输入提示词“使用playwright-cli，先打开X平台网站创建一个新的文章，然后把HTML的内容粘贴进去，找到所有的照相机小图标的位置，先按退格键删除掉小图标。然后在图片文件夹里面找到图片，先复制出来，按Ctrl+V再粘贴进去。小icon的数量跟图片的数量相等，按顺序替换”。
· 开始后AI为我们打开了浏览器，创建了一个新的草稿，把HTML格式的文章粘贴进去了。然后它开始一张张上传图片，把原来的占位符删除掉，再一张张替换成真正的图片。可以看到它正在自动化替换。
整个过程非常顺利，让AI把从头开始的全流程整理成一个skill，放到项目目录后，只要给它一个文章路径，告诉它使用这个skill自动发布，就能自动地把文章发布上去。这个skill的源代码已经上传到了GitHub仓库，感兴趣的观众可以参考。如果是其他操作系统，可以让AI参考这个skill来修改。相信按照这套流程大家都可以编写出属于自己的skill。
这套浏览器自动化流程一个重要的应用是对自己写的Web APP进行自动化测试。比如开发了一个简历润色美化的网页APP。
接下来输入指令“阅读代码，把从注册开始的主体流程写一个中文的测试文档，然后再用playwright CLI打开网页，根据测试用例完成测试”。
AI通过阅读代码学习到了这个项目的功能，然后确认了主体流程。
· 接下来开始编写测试文档，测试文档包含第一步做什么，第二步做什么，第三步做什么等。
· 然后AI使用playwright CLI打开了浏览器，它自动点击了注册按钮，创建了测试账号，完成了登录。它创建了一份测试简历并上传，完成了主体流程的测试。
测试结论是通过，也可以要求AI编写更多测试用例，使用playwright CLI进行全自动的测试。还可以使用OpenClaw这种带定时任务的Agent框架，让它定时对系统进行测试。一旦修改出现bug，AI就能全自动发现并告知，省去很多人工测试成本，对开发网页APP很有帮助。
