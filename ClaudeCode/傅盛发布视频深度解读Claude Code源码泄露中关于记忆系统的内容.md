
 
傅盛发布视频深度解读Claude Code源码泄露中关于记忆系统的内容，揭示了其“4+1”的记忆架构，包括四个记录系统和一个做梦系统，具体如下：
 
一、第一层记忆：CLAUDE.md文件
 
这是用户自行编写的文件，用于定义Claude Code记忆的大框架，涵盖“你是谁”“项目是什么”“规范是什么”等内容。其加载顺序分为四层，优先级则与之相反：
 
- 公司统一配置：云存储，所有人共用。
- 个人全局配置：对所有项目生效，个人编写。
- 仓库共享配置：代码仓库内团队共享。
- 本地私有配置：不提交仓库，本地私有。
加载顺序是1到4，优先级却是4到1，即距离用户越近的指令优先级越高，个人配置优先级高于公司规范。这意味着用户对AI Agent的个性化定义越清晰，AI越能满足个性化需求。
 
二、第二层记忆：自动记忆系统
 
Claude Code有一个独立的记忆提取Agent在后台同步运行，用户感知不到。它记录的内容分为四类：
 
- USER记忆：不断优化对“你是谁”的认知，包括身份、偏好、风格等。
- FEEDBACK记忆：记录你纠正和认可过它的内容，既记错误也记成功经验，避免Agent因只记纠正而变得保守。
- PROJECT记忆：记录项目的上下文、背景、代码结构等。
- REFERENCE记忆：记录外部资源链接、文档、历史记录等。
其中一个细节是，凡是涉及时间的内容，必须存储为绝对时间，例如将“下周四”存为“2026年4月10号”，防止记忆因时间表述模糊而失效添乱。
 
三、第三层记忆：上下文压缩机制
 
当记忆上下文满了时，Claude Code有三重压缩机制：微压缩、自动压缩、完整压缩，根据窗口剩余空间决定使用哪一层。自动压缩的触发条件是上下文窗口减去13000个Token的缓存后达到触发线。
压缩时，必须保留改了哪些文件、踩过的错误、用户所有反馈以及最后一条（若有下一步需原文引用最近对话原话）。此外，源码中有著名的三行代码注释，记录了因压缩失败导致的API调用浪费情况，强调AI产品需时刻优化缓存以节省成本。
 
四、第四层记忆：纯文件系统
 
Claude Code的记忆系统未使用向量数据库，而是采用纯文件系统。每条记忆是一个独立的Markdown文件，包含标题、类型、内容，支持人类直接阅读、手动修改，可通过git管理，能回滚和查看版本差异。
记忆索引文件MEMORY.md最多200行，每条不超过150字，超出则截断，保证索引精简。采用纯文件系统的好处是记忆可被人类审查，信任成本低，且方便用户在记忆系统不好用时直接打开修改规则，增强了用户对AI的控制感。
 
五、第五层记忆：AutoDream自动做梦系统
 
这是最魔幻的部分，源码中有一个名为AutoDream的模块，即“自动做梦”，是对记忆文件的反思性回顾。触发条件是距上次整理至少24小时且期间至少有5个工作session。
做梦分为四个阶段：
 
- 定向：搞清楚自己已知的内容。
- 收集：扫描当日日志，找出值得留存的新信息。
- 整合：将新信息写入记忆文件，把相对时间换成绝对时间，用新发现修正旧记忆，避免矛盾。
- 剪枝：删除过时、冷藏的记忆，更新索引，保持MEMORY.md在200行以内，节省记忆空间。
其中“记忆漂移”概念指当代码或情况变化导致某条记忆不再准确时，做梦机制会找出并修正这类记忆，确保记忆的准确性，这与人脑整理白天信息的记忆机制类似，是对人脑记忆认知的模拟。
 
傅盛表示，记忆系统是AI Agent产品的护城河，Claude Code的记忆系统做到了目前的极致，包括记忆分层、自动提取、压缩保鲜、文件审核、每晚做梦等，形成了一整套完整系统。一个越用越懂用户的AI和每次都从头开始的AI是完全不同的产品，做好AI产品，记忆是重中之重。
