深度拆解 Claude Code 架构原理-系列开篇：Claude Code 到底是怎么工作的？
 
今天聊一个很多人都会忽略的问题，Claude Code 到底是怎么工作的？不是宣传片里说的那么简单，AI 帮你写代码，它会自己读文件，自己改代码，自己跑测试，自己看结果，全程你只需要说一句话，剩下的全是它在推进。但你有没有想过，这个能力到底从哪里来？很多人会说模型变聪明了，错，模型本身只会生成文字，真正让它从“会说话”变成“会干活”的是外面那层工程系统，这就是我们这个系列要讲的核心——模型与工程系统的关系。
 
先问自己一个问题，模型本身只会生成文字，它不会自己打开文件，不会自己运行命令，更不会根据错误信息调整下一步。那 Claude Code 是怎么做到这些的？说到底靠的不是模型变聪明了，而是外面那层控制平面，一套让模型和真实世界持续交互的工程系统。模型只是“大脑”，外面那层工程才是“手脚和神经系统”。这个关系搞不清楚，后面的内容你听起来就会觉得散。
 
具体来说，这个控制平面在做五件事：
 
- 第一，模型想调工具，系统真的去执行，把结果再带回模型，让模型继续推理。
- 第二，任务拆成步骤，系统把当前进度外显出来，防止模型走一步忘一步。
- 第三，上下文越来越长，系统自动压缩，保留关键连续性信息。
- 第四，模型想执行危险操作，系统先过一道权限关卡。
- 第五，多个 Agent 同时工作，系统给每个任务分配独立工作空间，防止改文件打架。
 
这条工程主线才是 Agent 系统的真正骨架。这条工程主线里最核心的就是这个闭环流程，流程是：发请求给模型→模型想调工具→真的去执行→把结果写回消息历史→继续下一轮。这个回路立住了，后面的每一章都是往上面加新模块。
 
说白了，Agent 的本质不是模型很聪明，而是系统把模型的动作意图变成真实执行结果，再把结果送回模型继续推理。记住这句话，整个系列你就抓住了主线。
 
一环能跑了，但还不可靠，接下来就要加固。系统加固有五大模块：
 
- 第一，权限系统，工具意图不能直接变成执行，中间必须先过安全判断。
- 第二，Hook 系统，在固定时机插入行为，不用改主循环本身。
- 第三，记忆系统，跨会话保留真正值得长期记住的信息，而不是什么都往里塞。
- 第四，System Prompt 流水线，把提示词从硬编码复制串升级成多来源组装。
- 第五，错误恢复，遇到断链、超时、上下文超载，不崩溃，换一种方式继续。
 
这五个模块加上去，系统就从“能跑”变成“可靠”，单个 Agent 的能力基本够了，但大任务还需要更多。这就是第三阶段要解决的“任务运行时系统”，包含三个模块：
 
- 任务图系统：把 todo 升级成带依赖关系的工作图，可以追踪谁在等谁。
- 后台任务：慢命令移到后台执行，主循环不被堵住，继续推进别的事。
- 定时调度：不是现在做，而是“30 分钟后提醒我继续检查”。
 
这三个模块让系统从“单兵作战”升级到“有规划地推进复杂任务”，单兵作战到头了。最后升级成团队协作，构成多 Agent 平台架构，包含五个部分：
 
- Agent 团队：队友长期存在，是有名字、有邮箱、独立循环的持久工作者。
- 团队协议：关机请求、计划审批等全部走结构化请求，加 Request ID 和状态追踪。
- 自主认领：无人手动分配任务，空闲队友自己扫描任务板，按角色条件认领可做的工作。
- Worktree 隔离：每个并行任务在独立工作空间执行，互不污染，完事后决定是保留还是回收。
- MCP 协议：把外部工具接进来，成为可插拔的能力。
 
这五部分合起来就是一个完整的多 Agent 平台。
 
整个系列有一个一致的教学哲学，每个概念先区分“不是什么”，再讲“是什么”，然后给最小可用的实现，明确划定教学边界。这不是教你调 API 那种玩具 demo，是一个结构完整、生产级思维的教学版本。十九章分成四个递进阶段，从核心闭环到系统加固，再到任务运行时，最后到多 Agent 平台，一层层搭起来。
