【全栈观察员的作品】 https://v.douyin.com/HLfpn11g-is/ 

咱们聊ECC的设计哲学和四层架构，结尾提到了Skills层，一百八十二个可复用的技能卡片是整个项目最核心的创新之一

上周有个朋友跟我抱怨，说他用 Claude Code 写了一整天代码，Agent 突然发了疯，一口气改了五十个文件，方向全是错的，最后只能全部回滚。我问他：你的 soul.md 写了吗？他愣了一下，问：什么是 soul.md？今天咱们就来聊这个 soul.md 背后的项目 Everything Claude Code，一个在 GitHub 上拿到了超过十五万 Star 的项目，一百七十多个贡献者，覆盖十二种编程语言生态。
 
有人说它是 Claude Code 的最强配置包，有人说它是 AI 编程的作弊神器，还有人说它不过是一堆 Markdown 文件而已。那么真相到底是什么？咱们把它掰开了揉碎了好好聊一聊。这是本系列第一集，共七集。
 
这个项目的作者叫 Affaan Mustafa，二零二五年九月，他和搭档在一个周末参加了 Anthropic 举办的黑客松，四十八小时用 Claude Code 从零搭建了 zenith.chat，拿了冠军。黑客松赢了，但 Affaan 没停下来，他继续用了整整十个月，每天都在用 Claude Code 写真正的产品代码，每天都在踩坑、优化、迭代。一百八十二个 Skills，近五十个专业 Agent，六十八个 Commands，就这么一个一个攒出来了。
 
十五万 Star 不是靠营销刷出来的，是靠十个月的真实生产力换来的。所以这个项目到底做对了什么？答案是它解决了一个所有 AI 编程用户都会遇到的核心问题：怎么让 AI 代理真正可靠地帮你干活？
 
大多数人用 Claude Code 就是打开终端跟它聊天，让它写代码，想到什么 prompt 就写什么，想到什么配置就加什么。打个比方，你装修房子，你是随便买家具往里塞，还是先画设计图、分区规划再动工？大多数人就是随便塞，结果上下文窗口爆了，Agent 开始胡言乱语了，Token 账单上天了。
 
Everything Claude Code 的做法完全不一样，它的根目录下有一个文件叫 soul.md，里面只有五句话，但每句话背后都有十个月的踩坑血泪。
 
- 第一句：Plan Before Execute，先规划再动手。这就是开场那个朋友的遭遇，Agent 一次改了五十个文件，方向全错，全部回滚。为什么？因为没有先规划，ECC 要求复杂改动必须先拆成明确的阶段，一步步推进，而不是让 Agent 一把梭。
- 第二句：Agent-First，让专业的人做专业的事。不是让一个万能主线程干所有活，而是把工作路由到专业代理。就像一个公司不能让 CEO 既做销售又写代码又管财务。之前有个项目让主 Agent 一把梭，结果它一边写代码一边改需求文档，自己跟自己打架。规划任务有 planner，审查代码有 code-reviewer，查安全漏洞有 security-reviewer，每个代理只做一件事。
- 第三句：Test-Driven，先写测试再信代码。AI 给你写了个登录功能，界面漂亮逻辑自洽，但你一测密码明文存储。ECC 要求所有改动必须先过测试，不测试不让提交。这不是教条，这是无数次翻车换来的铁律。
- 第四句：Immutability，不要原地修改，用新的状态替换旧的。就像 Git 每次提交都是新的快照，而不是覆盖旧文件。两个 Agent 同时改同一个配置文件，A 刚写完 B 就覆盖了，debug 到凌晨三点，这就是不做不可变的代价。
- 第五句：Security-First，安全是底线不是选项。验证输入、保护密钥、默认安全配置，听起来简单，后面讲安全那一集你会看到 CVE 级别的真实安全事故，会让你后背发凉。
 
五条原则讲完了，那么它们怎么落地？Everything Claude Code 用了一个四层架构来承载。
 
- 第一层是 Rules，全局约束，放在 rules 目录下。Python 项目有 Python 的规矩，TypeScript 项目有 TypeScript 的规矩，什么必须做、什么绝对不能做，写得清清楚楚。比如永远不要在输出里包含 API Key，永远不要提交没测试的代码，这是整个系统的安全底线。
- 第二层是 Skills，可复用的工作流，放在 skills 目录下。一百八十二个 Skills，每一个都是一个可插拔的领域专家。你想做代码审查有 code-review 这个 Skill，你想做 TDD 开发有 TDD 这个 Skill，它们不只是简单的命令，而是包含上下文、参考资料、执行流程的完整工作包。Skills 是这个项目最核心的创新之一。
- 第三层是 Agents，专业代理，近五十个 Agent，每个有自己的专长、允许使用的工具、推荐的模型。架构设计用 Opus，日常编码用 Sonnet，搜索文档用 Haiku，这不是随便分配的，而是根据任务复杂度和成本精心设计的成本路由策略。
- 第四层是 Hooks，自动化质量保障。每次编辑完 TypeScript 文件自动格式化，每次 Claude 停下来自动检查有没有残留的 console.log，你不用时刻盯着 Agent，系统自己就能管好自己。
 
这四层不是各自为战的，打个比方，Rules 是宪法，Skills 是法律条文，Agents 是执法者，Hooks 是自动监控系统，它们一起构成了一个完整的工程治理体系，把一个本来只会聊天的 AI 变成了一个可靠的编程搭档。而且这个体系不仅支持 Claude Code，还支持 Cursor、Codex、Gemini CLI 等多个平台，一套配置多平台通用。
 
好了，咱们来回顾一下今天讲的重点。
 
- 第一，Everything Claude Code 不是配置集合，是一套经过十个月实战打磨的 AI Agent 工程方法论。
- 第二，soul.md 五条设计原则：Plan Before Execute、Agent-First、Test-Driven、Immutability、Security-First，每一条都是用真实翻车换来的教训。
- 第三，四层架构环环相扣：Rules 定规矩，Skills 教方法，Agents 派人手，Hooks 做质检。
 
如果你现在就想试试，打开 GitHub 搜索 everything.claude-code，按照 README 两分钟就能装好。装完之后开个新会话，输入 /plan 加上你想做的功能，你就能立刻感受到 ECC 的工作流约束是什么感觉。
 
下一集我给你看一个东西，一个能让 AI 自己学会用新工具的机制，它叫 Skill。Everything Claude Code 里有一百八十二个这样的 Skill，其中有一个叫圣诞老人验证法，顾名思义它会把你写的代码像检查圣诞礼物一样一件一件验。你猜它怎么验的？下集告诉你。
