# Claude Code 完整学习指南 - 每章总结

## 前言

**主要议题**: Claude Code的本质与学习路线

**关键观点**:
- Claude Code不只是一个ChatGPT的CLI版本，而是**Agent编排框架(Agentic Harness)**
- Anthropic官方定义：提供了工具、上下文管理、执行环境的完整体系
- 同一模型在不同Harness下的表现差异**远大于**不同模型在同一Harness下的表现差异
- Harness比模型本身更重要

**核心启示**:
- 2026年行业洞察：优化Harness的收益比等待更强模型更显著
- 本书将Claude Code的90%隐藏能力交到你手中

## 第1章：登高望远—Claude Code技术架构全景

**主要议题**: Claude Code的整体架构与四层模型

**核心概念**:

### 从命令行助手到Agent框架
- 表面：终端对话、代码生成、命令执行（10%的冰山）
- 深层：完整的框架与基础设施（90%的冰山）

### 四层架构模型
1. **记忆层(CLAUDE.md)** — 地基
   - 解决"失忆"问题
   - 5层级记忆体系（企业→用户→项目→规则→本地）

2. **扩展层(四大组件)** — 主体楼层
   - Commands（斜杠命令，手动触发）
   - Skills（技能，自动匹配）
   - SubAgents（子智能体，隔离执行）
   - Hooks（事件钩子，自动守护）

3. **集成层(Headless & MCP)** — 水电管网
   - Headless模式：无人值守运行
   - MCP：连接外部系统

4. **编程层(Agent SDK)** — 顶楼工作室
   - 从使用者转型为构建者

### Agentic Loop机制
- 观察→假设→验证→行动的循环
- 不是一次生成，而是反复推理与迭代
- 循环终止条件：模型停止或达到max-turns

**关键公式**: `Agent = Model + Harness`

## 第2章：温故知新—记忆系统工程实践

**主要议题**: CLAUDE.md配置与5层记忆体系

**核心问题**: 
- 为何Claude每次都"失忆"？因为它是无状态模型，每轮对话都从零开始
- 如何解决？通过CLAUDE.md构建"员工手册"

### 五层记忆体系
| 层级 | 位置 | 范围 | 典型用途 |
|-----|-----|------|--------|
| 企业级 | managed-settings.json | 全员 | 安全底线、合规策略 |
| 用户级 | ~/.claude/CLAUDE.md | 个人 | 个人编码偏好 |
| 项目级 | ./CLAUDE.md | 团队 | 技术栈、规范约定 |
| 规则级 | .claude/rules/*.md | 条件化 | 特定场景规则(按需加载) |
| 本地级 | ./CLAUDE.local.md | 个人 | 私人备忘(不提交) |

### 写作范式："少即是多"
- 每一行文字都是Token成本
- 超过150条指令会显著降低遵循质量
- 三问框架：WHY(为什么) / WHAT(做什么) / HOW(怎么做)

### 条件化规则系统
- `.claude/rules/`目录实现模块化
- 通过paths Glob模式精准触发
- 按需加载，零浪费Token

## 第3章：授人以渔—Skills工程实践

**主要议题**: Skills是专业领域知识的标准化封装

**核心关键词**: CLAUDE.md vs Skills
- CLAUDE.md：规章制度（墙上的标语，始终有效）
- Skills：SOP操作手册（文件柜，需要时翻阅）

### Skills架构
目录结构：
```
skill-name/
├── SKILL.md              # 核心指令（文件名必须大写）
├── scripts/              # 可执行脚本
├── reference/            # 按需加载文档
└── templates/            # 输出模板
```

### 关键特性

**1. 渐进式披露(三层)**
- 扫描阶段：仅加载description（98%节省）
- 激活阶段：加载SKILL.md（85%节省）
- 执行阶段：按需加载reference文件

Token消耗对比示例：全量5300 vs 分阶段1800（节省66%）

**2. description预算机制**
- 总预算：上下文的2%（默认16,000字符）
- 按Skill数量平分
- 超预算自动排除

**3. 两种触发模式**
- **参考型**（默认）：Claude自动匹配触发
- **任务型**（disable-model-invocation: true）：用户显式调用

### 4种设计模式
1. 模板驱动：预定义输出格式
2. 脚本增强：封装确定性计算
3. 知识分层：80/20法则（80%请求仅需20%知识）
4. 工具隔离：allowed-tools严格权限

### 测试与迭代
- 触发测试：90%+触发率，<5%误触发
- 功能测试：输出格式、覆盖完整性
- 性能对比：有Skill vs无Skill

## 第4章：分而治之—子智能体与任务委派的艺术

**主要议题**: 通过隔离上下文来分解复杂任务

**核心问题**: 上下文污染
- 5000行日志+200行测试输出 = 信噪比失衡
- 后续5轮对话都要重复传输这些噪声

### 子智能体的3大价值
1. **隔离** — 独立上下文窗口，噪声不泄露
2. **约束** — 工具权限白名单，只做该做的事
3. **复用** — 可共享、可迁移的模块化组件

### 5种子智能体模式

| 模式 | 特征 | 场景 | 工具权限 |
|-----|------|------|--------|
| 只读型 | 观察、分析，不修改 | 代码审查、安全审计 | Read, Grep, Glob |
| 执行型 | 处理高噪声任务，仅返回摘要 | 日志分析、测试运行 | 广泛(受控) |
| 并行型 | 多个独立任务并发执行 | PR多维度审查 | 各异(隔离) |
| 流水线型 | 多阶段顺序处理，上游输出=下游输入 | Bug修复全流程 | 按阶段调整 |
| 团队型 | 长期持续协作，成员间可通信 | 复杂重构协同 | 灵活配置 |

### 与Skills协作
- **方向A**：子智能体预加载Skill（子包含Skill）
  - 子智能体=执行者，Skill=操作手册
  
- **方向B**：Skill派生子智能体（Skill包含子智能体）
  - Skill=调度者，子智能体=执行容器

### Token经济学
不使用子智能体：125,000 Tokens（5轮后）
使用子智能体：116,500 Tokens（节省6.8%）

关键收益（不仅是成本）：
- 上下文窗口保护（防止信息丢失）
- 响应质量提升（聚焦度高）

**启用决策**：当输入>>输出时，启用子智能体

## 第5章：防微杜渐—Hooks事件驱动自动化

**主要议题**: 系统执行层面的强制约束

**工作层面对比**
| 机制 | 工作层面 | 约束性质 | 效果 |
|-----|--------|--------|------|
| CLAUDE.md | 认知层 | 建议 | 交通标志 |
| Skills | 认知层 | 指导 | 驾驶手册 |
| Hooks | 系统执行层 | **强制** | 路障 |

### 17个事件（核心3个）
1. **PreToolUse** — 工具执行前拦截（最强大）
2. **PostToolUse** — 工具执行后反馈
3. **Stop** — 任务完成时质量门控

### 3种处理器类型
| 类型 | 确定性 | 灵活性 | 延迟 | 场景 |
|-----|-------|--------|------|------|
| command | ★★★★★ | ★ | 0ms | 模式匹配 |
| prompt | ★★★ | ★★★ | 2s | 单次评估 |
| agent | ★★ | ★★★★★ | 30s | 多轮分析 |

### 6层配置位置
从企业级到子智能体Frontmatter，优先级递减

### 完整防护体系（本章案例）
1. **PreToolUse**：危险命令拦截 + 敏感文件保护
2. **PostToolUse**：自动格式化 + Lint反馈
3. **Stop Hook**：测试质量门控

### 设计方法论："三步走"
1. 先部署审计日志（观察实际行为）
2. 基于数据设计拦截规则
3. 逐步收紧，保留审计日志

## 第6章：海纳百川—MCP（模型上下文协议）

**主要议题**: 标准化的AI工具集成协议

**核心问题解决**
- 前MCP：$M \times N$问题（M个AI × N个数据源 = MN个适配器）
- 后MCP：$M + N$问题（M个AI + N个数据源，仅需M+N个实现）

类比：USB-C的标准化，解决充电线混乱

### MCP三大核心能力
1. **Tools** — Claude调用的函数
2. **Resources** — Claude读取的只读数据
3. **Prompts** — 可复用的提示词模板

### 传输方式
- **stdio** — 本地进程通信（安全，低延迟）
- **HTTP** — 远程服务器（支持OAuth2）
- **SSE** — 已废弃

### 配置与使用
```
.mcp.json: 声明式配置
├── 本地stdio服务器
├── 远程HTTP服务器
└── 环境变量替换(如 ${DATABASE_URL})
```

### MCP + Skills = "厨房与菜谱"
- MCP提供设备与原料（数据库、API、文件系统）
- Skills提供操作指南（如何调用MCP工具）

### 安全机制（三层）
1. 首次连接交互式审批
2. 细粒度工具级权限控制
3. OAuth 2.0动态认证

### 常用MCP生态
官方：filesystem, fetch, postgres, memory, git
第三方：GitHub, Notion, Sentry

## 第7章：无为而治—Headless模式与CI/CD集成

**主要议题**: Claude在无人值守环境下自动运行

**本质转变**
- 交互模式：人机对话，人工确认每一步
- Headless模式：一次性输入，自动执行，无人干预

### 4维度参数体系

1. **输出格式控制**(--output-format)
   - text: 纯文本
   - json: 结构化(包含cost、turns等元数据)
   - stream-json: NDJSON流式

2. **成本护栏**
   - --max-turns: 防过度分析
   - --max-budget-usd: 防失控成本
   - 两个参数都要配置

3. **安全边界**(--allowedTools)
   - 白名单优于黑名单
   - 支持模式匹配(如Bash(git log *))

4. **执行控制**
   - --model: 模型选择
   - --system-prompt vs --append-system-prompt
   - --json-schema: 强制输出格式

### Unix管道集成
Claude成为命令行工具链中的一环：
```bash
git diff | claude -p "总结变更" | jq '.result'
```

### CI/CD集成
两种方案：
1. **官方Action**(anthropics/claude-code-action) — 配置简单
2. **直接CLI** — 灵活性强

### 多阶段流水线
- 模型分级：Haiku(快速) vs Sonnet(深度)
- 预算分级：简单任务$0.05 vs复杂$1.00
- 并行执行：多个阶段同步运行

### 流式输出实时监控
stream-json格式支持实时观测长耗时任务

### 生产级清单
必须环境变量：ANTHROPIC_API_KEY, CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC
性能参数：BASH_DEFAULT_TIMEOUT_MS, MAX_MCP_OUTPUT_TOKENS
**容器隔离**：--read-only + --network none

## 第8章：器以载道—Agent SDK智能体开发套件

**主要议题**: 从工具到可嵌入组件

**本质转变**
- Headless模式：参数驱动Claude
- Agent SDK：代码编程Claude

### 核心API

**query函数**（入口）
- 返回异步生成器，不阻塞等待
- 支持实时流式处理

**消息类型**（消息流解读）
| 类型 | 含义 | 用途 |
|-----|------|------|
| system/init | 会话初始化 | 验证工具、MCP状态 |
| assistant | Claude响应 | 提取思考过程、工具调用 |
| user | 工具结果 | 反馈执行结果 |
| result | 任务完成 | 成本、轮数、元数据 |

**ClaudeAgentOptions**（精细控制）
- 权限模式：default / acceptEdits / plan / bypassPermissions
- 工具白名单：支持模式匹配
- 会话恢复：--resume / --fork-session

### 权限模式详解
| 模式 | 行为 | 场景 |
|-----|------|------|
| default | 询问 | Web应用 |
| acceptEdits | 自动接受编辑 | 自动修复脚本 |
| plan | 仅分析不执行 | 代码审查 |
| bypassPermissions | 完全信任 | 隔离容器 |

### 会话管理
- 基于session_id继续对话
- fork_session进行分叉探索
- 跨调用保持上下文

### 自定义工具
@tool装饰器 → 进程内MCP服务器
```
mcp__app-tools__query_database
```

### 4道安全防线（纵深防御）
1. permission_mode全局开关
2. allowed_tools工具白名单
3. canUseTool运行时回调
4. PreToolUse Hooks参数检查

### 结构化输出
通过output_format + json_schema强制JSON格式
自动重试，超限返回error_max_structured_output_retries

### Agent SDK vs Headless CLI
| 场景 | 推荐 | 原因 |
|-----|------|------|
| CI单步任务 | CLI | 零依赖 |
| Web应用 | SDK | 流式输出 |
| 自定义工具 | SDK | @tool支持 |
| 多轮对话 | SDK | session管理 |

**经验法则**：能一行命令描述→CLI；需if/else→SDK

## 学习路线总结

### 四个层级的进阶路径

```
Level 1: 基础使用者
├─ CLAUDE.md配置
├─ 基本CLI操作
└─ 理解四层架构

Level 2: 中级开发者
├─ Skills设计与部署
├─ Hooks配置
├─ 子智能体应用
└─ Headless CLI集成

Level 3: 高级工程师
├─ MCP自建与集成
├─ 复杂CI/CD流水线
├─ Agent SDK开发
└─ 跨项目最佳实践

Level 4: 架构师
├─ Plugins生态设计
├─ 企业级部署
├─ 团队培训与标准化
└─ 成本与安全治理
```

### 核心设计哲学

1. **分离关注点** — CLAUDE.md(规范) / Skills(知识) / Hooks(守护)
2. **递进式复杂度** — 从配置到代码，循序渐进
3. **最小权限原则** — 只授予必需权限
4. **可观测性** — 审计日志、成本追踪、性能监控
5. **团队可扩展** — 模块化、可复用、易分享

### 最常用的组合

| 场景 | 组合 |
|-----|------|
| 团队编码规范 | CLAUDE.md + Hooks |
| 自动代码审查 | Skills + Hooks + Headless CLI |
| 复杂分析 | SubAgents + MCP + Skills |
| Web应用 | Agent SDK + 自定义工具 + 权限模式 |

---

**最后的话**：
从CLAUDE.md的配置，到Skills的知识封装，到Hooks的自动守护，再到MCP的外部连接，Headless模式的自动化，最后到Agent SDK的完整编程——每深入一层，你就离"构建产品"而非"仅用工具"更近一步。选对工具，用好机制，Claude Code 就是打开AI工程化时代的钥匙。
