Claude 不严格遵守 CLAUDE.md，Claudemd 写得再细，这事你肯定遇到过 Anthropic。规则明明白白写在那儿，CLAUDE.md content is delivered as a user message after the system prompt, not as part of the system prompt itself. 翻译过来就是——读了，但没有强制执行的承诺，模型也读了，但执行到某一步它就是绕过去了。这一期我想跟你聊清楚——1 为什么 2 怎么解决。
 
先说一句这是一个系列，前两期讲了 Claudemd 怎么写、claude 目录下五层配置都干嘛用，从这一期开始我们其实在做一件更大的事，把 ClaudeCode 这套东西搭成一条你可以每天照着走的工作流。
 
今天讲的是这条工作流里最容易被低估的一层——Hooks。为什么会这样？Anthropic 自己在官方文档里写得很清楚，他们把 Claude Code 的能力分成了四层：
 
- 如果 Claude 每次都该知道的事 → CLAUDE.md
- 如果有时需要 → Skill 或 rules
- 如果必须每次都发生 → Hook，也是本期视频重点讲的
- 如果某类能力根本不该碰 → permissions
 
这四层最容易被混着用的就是第三层 hook 这一层，很多人压根不知道它存在或者知道但没意识到它解决的是个完全不一样的问题。
 
那 Hook 到底是啥？先问你，你是不是遇到 Claude 不听话的情况？那可不是你的提示词有问题，Hook = 100% 执行，提示词 = 看心情，提示词是软约束，而 hook 是 100% 执行。
 
告诉我你的 Claude 是经常不听话吗？我曾经让 Claude 帮我清个临时目录，它自己拼了个  rm -rf  出来，因为之前在项目目录下已经手动确认跳过这个执行权限，所以自动执行了。还好那是测试目录，但背后真的凉了一下。
 
一句话讲明白 hook 是什么？它是 ClaudeCode 在自己生命周期的关键节点上，让你挂一段强制脚本的入口，用户提交 prompt 之前、工具调用之前、工具调用之后、对话结束等等。官方文档列了三十多个事件，但实际上你只要先记住两个就够用，主力先用：
 
- 01 PreToolUse → 工具跑之前拦
- 02 PostToolUse → 工具跑完之后接
 
先把前两个用熟，剩下的什么时候要用什么时候再加。这个视频我也是通过 Claude Code 制作出来的，后面把知识点讲完会以这个工作流为例讲解。
 
我先分享下我每天都用的三个场景，你看完直接抄如何使用：
 
1. PostToolUse 配自动格式化：Claude Code 每次 Edit 或者 Write 完一个文件，自动跑 prettier 或者格式化工具。配置就六行，JSON 中 matcher 写 Edit、Write，配置命令中写 prettier 加文件路径。从此你 CLAUDE.md 里就不用再写“记得格式化”这种话了，它一定会发生。本质区别：提示词是约定，Hook 是强制。
2. PreToolUse 拦危险命令：之前 Claude 没让我确认就执行了  rm -rf  操作，在那之后我加了一个 hook，在配置中加上了这个命令的 hook，匹配上就调一个脚本，脚本里再判断一次完整命令，遇到  rm -rf  直接  exit 2 。退出码 2 这个细节非常关键，stderr 回传给 Claude，让它知道发生了什么。
3. Stop 事件配桌面通知：我经常让 Claude 跑一个比较慢的任务，自己切去干别的，回来发现它早就停在那儿等我了。配上 Stop hook 之后，它一收尾桌面直接弹出来消息，我直接确认就好，不用我主动去查看。
 
但我得说一个反话——Hooks 不是越多越好，这事挺微妙。如果某件事“不是每次都该发生”，硬塞进 hook 反而会变成新的污染源。它适合勾住那些“确定性的、每次都得做的、不需要思考的”动作。
 
判断标准很简单：你能不能用一个 shell 脚本写完这段逻辑，且永远不变。能 → 上 hook；不能 → 别用。
 
回到开头那个反差点，CLAUDE.md 写得再认真也只是契约，契约靠双方履约，你方履约了，Claude 这边偶尔走神。一个判断标准你可以直接拿走：如果你 CLAUDE.md 里某条规则你发现自己会反复去强调，这件事就该下沉到 hook。提醒是可跳过的，hook 是硬约束。
