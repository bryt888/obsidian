大家好，今天来深入了解Claude Code。首先为大家介绍Claude Code的核心定位，它本质上是一个运行在终端上的智能代理助手。“终端”意味着它通过命令行工作，“智能代理”则说明它不仅能执行命令，还能推理、规划、做决策。
 
虽然Claude Code最初设计和优化用于编程任务，但实际上是通用工具，能完成终端上的任何任务，比如编辑文档、运行构建任务、搜索文件内容，甚至研究某一技术主题。其核心公式是：Claude Code = 大语言模型 + 工具 + 执行环境，这说明它将强大的语言模型与实际可执行工具结合，是能真正完成任务的助手，而非单纯聊天机器人。
 
它的核心工作模式是Agentic Loop三阶段循环：
 
- 收集上下文：当给Claude Code任务时，它会先理解当前环境和需求，包括搜索相关文件、理解代码结构、提取配置文件等，会使用grep命令搜索，用read工具提取文件内容，这是正确完成任务的基础。
- 执行操作：有了足够上下文后，开始执行具体操作，如编辑文件、创建新文件、运行shell命令、启动服务器等，每次操作都推进任务完成。
- 验证结果：操作后确认结果是否符合预期，常见方式有运行测试套件、检查命令输出、验证文件变更等。若验证失败，会重启循环，收集更多上下文。
 
循环有几个特点：用户输入是循环起点，用户可在任何时候中断循环；循环具有高度适应性，会根据任务复杂度区分。比如简单查询类任务（解释代码、回答概念性问题），仅需收集上下文阶段；bug修复类任务需完整三阶段；重构类任务也需完整循环，且验证阶段更复杂，用户是循环的重要参与者，可随时中断并引导。
 
用户参与循环的方式有：随时中断、引导方向掌控大局、提供明确上下文信息、补充额外信息提升准确性、尝试不同方法或要求换一种思路。
 
循环包含两大关键模块：推理（大语言模型）和行动（各种工具）。模型方面，官方模型最佳，国内使用可切换其他模型，切换方式是用 model 命令，也可在启动时指定。
 
五大工具类别：
 
- 搜索工具：主要是grep、glob操作。
- 文件操作：主要是读写、编辑操作。
- 执行工具：执行shell脚本、bash或npm test等测试脚本。
- Web工具：进行Web搜索或拉取内容。
- 代码智能工具：类型检查、定义跳转、引用查找等。
 
关于会话（session），每次与Claude Code的对话都会被保存为JSON文件，存放在 ~/.claude/projects/ 路径中，记录交互环节、调用的工具、执行结果等。会话相关命令有：
 
- 续接之前未完成或中断的会话： claude --continue 
- 恢复特定会话： claude --resume <会话ID> 
- 分支并行会话： claude --continue --fork-session ，新会话上下文窗口空白，不继承历史。
 
上下文窗口是理解Claude Code工作原理的核心概念，可视为它的“工作记忆”，包含对话历史、文件内容、命令输出、自动记忆、加载的技能、指令系统等，影响处理任务的复杂度。当窗口满时，会触发自动压缩机制：
 
- 第一步：清除旧的工具输出，优先删除已验证不需要的工具调用详细内容，保留原始请求。
- 第二步：若空间仍不足，总结对话，将对话压缩为结构化代码，保留意图和关键代码，删除详细过程，过早的详细指令可能丢失。最佳实践是将持久规则放在 .claude.md 非对话上下文文件中。
 
优化上下文使用的策略：
 
- 明确指定文件范围：比如修复具体bug，而非模糊的“修复登录问题”，让Claude Code仅读取少量相关文件。
- 使用Subagents子代理委托：对于独立的研究任务，创建子代理完成，子代理返回摘要给主会话，适合信息收集类任务。
- Skills技能按需加载：通过设置命令让不需要的技能保持沉默，不占用空间。
- 延迟加载MCP工具：工具定义仅在使用时加载，启动时保持轻量。
 
Claude Code的双重安全机制：
 
- 检查点（Checkpointing）：确保文件变更可逆，每次编辑文件前自动创建记录，出现问题可按 Ctrl+E 回滚或让Git请求撤销。注意检查点是本地内容，与Git分开，不影响远程操作。
- 权限控制（Permissions）：控制工具使用权限，防止未授权操作，可通过快捷键切换权限模式。
 
权限模式有四种，可精确控制Claude Code的操作范围：
 
- Default模式：每次执行文件编辑和shell命令都会询问，最安全，适合对操作不熟或处理不信任来源代码时使用。
- Auto-accept edits模式：自动接受文件编辑和常见系统指令，对可能造成重大影响的命令仍会询问，是平衡之选，适合对项目有基本了解时使用。
- Plan mode模式：仅允许读取工具，不执行协助操作，会分析请求并创建详细执行计划供审批，适合大型重构或高风险操作。
- Auto mode模式：后台安全检查模式，在后台研究预览，不执行实际操作，是实验性模式。
 
还可在 .claude/settings.json 中配置允许特定命令，示例：
 
json
  

{
  "permissions": {
    "allow": ["Bash(ls -la)", "Bash(git status)"]
  }
}
 
 
使用Claude Code高效工作的四条核心原则：
 
- 像对话一样迭代：不要试图写完美提示词，而是描述目标，让它开始工作，再根据结果迭代改进。
- 具体明确：在迭代中给出具体指定，避免模糊请求。
- 提供验证标准：告诉它如何验证成功，比如提供测试用例。
- 先探索后实现：对不熟悉的代码库或复杂任务，先用Plan mode分析，理解架构和依赖关系，提出计划后再执行。
 
核心要点回顾：
 
- 代理循环：用户→收集上下文→执行→验证→循环→完成。
- 上下文管理：上下文窗口有限，会自动压缩，持久规则需放在 .claude.md 中。
- 安全机制：Checkpointing保障文件变更可逆，Permissions控制工具使用。
- 权限模式：精准控制Claude Code的操作范围。
