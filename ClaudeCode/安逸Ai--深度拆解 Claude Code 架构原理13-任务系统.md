深度拆解 Claude Code 架构原理（12）
 
大家好，我是安逸。今天继续深入 Claude Code 架构原理系列，第12期讲任务系统。这期会从为什么需要任务系统讲起，带你搞懂核心概念和关键数据结构。接着手把手实现最小任务图，最后还会区分它和代办、写入后台任务的边界。搞明白这些就能理解 Claude Code 是怎么把 todo 升级成持久化任务图的。直接开始。
 
先说个现实问题，拖动列表虽然能把大目标拆成几步，但它有两个明显限制。
 
- 第一，它更像当前会话里的临时清单，关掉就没了。
- 第二，它不擅长表达谁先谁后谁依赖谁。比如有个工作流，包含写解析器、做语义检查、运行、跑测试、写文档，最后整体验收。这已经是一张依赖关系图了，而不是普通清单，没有专门的任务系统，Agent 很容易在前面工作还没做完时就贸然开始后面的，或者完成后不知道该解锁谁。所以需要把 todo 升级成可持久化的任务图。
 
先把几个关键概念理清楚。
 
- 任务：指的是一个可以被跟踪、被分配、被完成、被阻塞的小工作单元。注意它不是整段用户需求，而是拆出来的一小块。
- 依赖：任务 B 必须等任务 A 完成才能开始。
- 任务图：任务节点加上依赖连线，可以理解成点和线，点是每个任务，线是“谁依赖谁”。
- Ready：表示这条任务现在已经满足开工条件，也就是自己还没开始，同时前置依赖全部完成了。
 
理解这些概念后，后面看代码就顺了。
 
来看最关键的数据结构 TaskRecord，每个字段都对应一个很实用的问题。ID 是怎么唯一找到这条任务？subject 是这条任务一句话在做什么？description 是还有哪些补充说明？status 是现在走到哪一步？blockedBy 是这条任务还在等谁？blocks 是它完成后会解锁谁？owner 是现在由谁来做？其中，blockedBy 和 blocks 这一对字段非常关键，它们让系统能同时从前往后和从后往前读懂依赖关系。
 
教学版先只保留 4 个状态：pending（还没开始）、in_progress（已经有人在做）、completed（已经做完）、deleted（逻辑删除，不再参与工作流）。这章最关键的一条判断规则是  is_ready ，它检查任务是否满足开工条件。一个任务要 ready，必须  status=pending ，同时  blockedBy  列表为空。
 
这条规则看起来简单，但它是整个任务系统运行的核心。很多初学者只会创建任务，却不懂维护依赖，问题就出在没有正确理解这条规则。现在开始手把手实现。
 
- 第一步：任务落盘。不要只把任务放在内存或 messages 里。教学版最简单的做法是在  tasks/  目录下，以“一任务一文件”的方式存储，比如  task_1.json 、 task_2.json  这样的文件。创建任务时直接把任务对象写成 JSON 记录落盘，这样系统重启后工作结构还在。这步很基础但很关键，很多初学者任务只放内存，重启就全丢了。
- 第二步：维护双向依赖。当任务 A 完成后会解锁任务 B 时，最好同时维护两边，让 A 的  blocks  列表里有 B，同时让 B 的  blockedBy  列表里有 A。这样做的好处是从前往后、从后往前都能读懂依赖关系，系统能双向推导依赖关系。如果只维护单项，后续很多操作都会变得复杂甚至出错。
- 第三步：自动解锁后续任务。当一个任务状态变成  completed  后，系统会遍历所有任务，找出  blockedBy  里包含当前任务的其他任务，把对应的依赖移除。这个机制非常关键，因为它说明任务系统不是静态记录表，而是会随着完成事件自动推进的工作图。没有这个机制，系统永远不知道下一步谁可以开工。
 
工具接口设计：
 
- 第四步：把任务工具给模型。教学版建议先做四个工具： task_create （新建任务）、 task_update （更新状态）、 task_get （查看单条）、 task_list （查看看板）。这样模型就能在用户提出复杂目标后，决定先拆任务，调用创建和更新接口，让任务落到  tasks/  目录，后续轮次继续读取并推进。
 
从这里开始，主循环第一次拥有了会话外状态。记住一句话：todo 更像当前会话里的快速步骤，task 更像长期工作板。必须把这三者的边界讲清楚。如果只是“先看文件、再改代码、再跑测试”，todo 往往就够了。任务系统适合持久化工作、多人协作且要管依赖的场景。教学版里的 task 指的是一条工作目标，回答“要做什么、现在做到哪一步、谁在等谁”，它不是正在后台跑的 Python 程序，不是正在执行的 worker，不是某条当前活着的执行现场。后面这些属于下一章要讲的“运行中的执行任务”，混淆这一层后面就很难讲清了。
 
最后总结，任务系统的核心能力是依赖关系 + 持久化。TaskRecord 是最关键的数据结构， blockedBy  和  blocks  让系统能看懂前后关系。如果这几点你都清楚，说明你能从 0 到手写一个最小任务系统。
