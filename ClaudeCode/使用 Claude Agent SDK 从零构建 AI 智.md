使用 **Claude Agent SDK** 从零构建 AI 智能体（Agent）是一个将 LLM 转化为能够自主决策、操作文件系统并验证结果的系统的过程。该 SDK 建立在 Anthropic 开发 **Claude Code** 的经验之上，其核心理念是利用 Unix 原语（如 Bash 和文件系统）来赋予智能体极高的灵活性 [1, 2]。

以下是根据源文件总结的构建步骤与核心设计指南：

### 1. 理解智能体循环（Agent Loop）的设计
构建智能体时，你需要围绕一个三阶段的循环进行设计：
*   **收集上下文 (Gather Context)：** 智能体需要能够主动寻找完成任务所需的信息 [3]。例如，在处理代码库时通过 `grep` 搜索相关文件，或在处理邮件时搜索特定的收件箱内容 [3, 4]。
*   **采取行动 (Taking Action)：** 智能体可以通过调用预定义工具、运行 Bash 命令或生成并执行代码（CodeGen）来执行任务 [3, 5]。
*   **验证工作 (Verifying Work)：** 这是最关键的一步 [3]。你需要设计验证机制（如编译检查、代码 Lint 或通过子智能体进行评审）来确保结果的准确性 [6, 7]。

### 2. 配置核心组件
在 SDK 环境中，智能体不仅仅是一个 Prompt，它是一个包含以下要素的**马具 (Harness)**：
*   **文件系统与上下文工程：** 建议使用文件系统来管理上下文，而非将所有信息填入 Prompt [8]。你可以使用 `cloud.md` 文件来定义智能体的身份、可用 API 和操作指南 [9, 10]。
*   **Bash 工具：** 来源强调 **“Bash 就是你所需要的一切” (Bash is all you need)** [11]。Bash 允许智能体存储工具结果、动态生成脚本、使用现有软件（如 ffmpeg）以及组合各种功能 [4, 12]。
*   **沙箱环境 (Sandboxing)：** 由于智能体具有 Bash 执行权限，必须在隔离的容器（如 Docker）中运行，并对网络请求和文件操作进行限制，以实现“瑞士奶酪防御”安全模型 [13, 14]。

### 3. 定义行动方式：工具 vs. Bash vs. 代码生成
你需要根据任务类型选择合适的交互方式 [5]：
*   **工具 (Tools)：** 适用于原子化、不可逆或需要高度控制的操作（如“发送邮件”或“写入文件”） [15]。
*   **Bash：** 适用于可组合的任务（如搜索文件夹、运行测试），且其上下文占用较低 [15, 16]。
*   **代码生成 (CodeGen)：** 适用于高度动态的逻辑处理，例如进行复杂的数据分析或调用多个 API [17, 18]。**实战技巧：** 如果遇到复杂的 API，可以先让智能体通过代码生成为该 API 编写一个 TypeScript SDK，而不是手动定义上百个工具调用 [10, 19]。

### 4. 进阶功能应用
*   **技能 (Skills)：** 当任务需要特定领域的专业指令（如前端设计或文档处理）时，可以创建“技能”文件夹。智能体在需要时会主动读取其中的指令，实现**渐进式上下文披露** [20, 21]。
*   **子智能体 (Sub-agents)：** 它是管理上下文污染的利器 [22, 23]。对于大型任务（如并行总结多个文档），可以派发多个子智能体处理并仅汇总最终结果回主智能体 [23, 24]。
*   **内存管理：** 可以直接在文件系统中创建一个 `memories` 文件夹，让智能体将重要信息写入其中，作为其长期记忆系统 [25]。

### 5. 从原型到生产的建议
*   **保持简单但优雅：** 智能体的代码量不需要很大，但设计逻辑应符合模型的偏好（例如将数据转换为模型熟悉的 SQL 或 XML 格式） [26-28]。
*   **快速迭代：** 建议先在本地使用 Claude Code 进行原型测试，观察智能体在处理任务时的推理轨迹（Transcripts），找出它在哪里遇到了瓶颈，然后针对性地优化 `cloud.md` 或增加验证逻辑 [29, 30]。
*   **确定性优先：** 在验证环节，尽可能多地引入确定性的规则（如文件读取检查、语法分析等），这比完全依赖模型自我检查更可靠 [7, 31]。
