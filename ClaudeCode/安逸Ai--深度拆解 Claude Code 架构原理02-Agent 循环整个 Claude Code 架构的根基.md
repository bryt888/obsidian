深度拆解架构原理
Agent 循环
整个 Claude Code 架构的根基。语言模型本身 ≠ 会干活的 Agent，除非有一层代码在中间反复做这件事。很多人以为接入了大模型，AI就能帮你干活了，但真相是，语言模型本身只会生成下一段内容，它不会打开文件，也不会观察报错。在中间反复做这件事：发请求给模型，发现模型也想调工具，真的去执行工具，把结果再喂回模型，继续下一轮。那模型就只是一个会说话的程序，还不是一个会干活的agent。这就是我们今天要讲的agent循环，也是整个cloud code架构的根基。
 
四个核心概念
在说循环之前，先把几个名词搞清楚。就是循环，意思是只要任务还没做完，系统就继续重复同一套步骤，可以理解成一轮。最小版本里，一轮包含把当前消息发给模型读取，模型回复；如果模型调用了工具，就执行工具，然后把工具结果写回消息历史，之后才进入下一轮。第三个是tool result，就是工具执行结果，它不是随便打印在终端上的日志，而是要重新写回对话历史，让模型下一轮真的能看见的结果块。第四个是state，是当前运行状态，也就是主循环继续往下走时，需要一直带着走的那份数据，最小版本里，就是messages和当前是第几轮。
 
最小心智模型
把整个agent想成一条回路：用户消息进入LLM，如果给出普通回答直接结束；但如果它想调用工具，就去执行工具，然后把工具结果写回message，再继续下一轮，一个while true循环。这工具结果必须重新进入消息历史，成为下一轮推理的输入，如果少了这一步，模型就无法基于真实观察继续工作，它就只能永远停留在想象层面。
 
三个关键数据结构
不要用零散局部变量，显式装填循环状态更清晰。接下来三个关键数据结构：第一个是message，消息就是raw和content字段，这里最重要的不是字段名字，而是要记住，消息历史不是聊天记录展示层，而是模型下一轮要读的工作上下文。第二个是tool result block，当工具执行完后，要把它包装成type为result的消息块，里面要有tool_use_id，用来告诉模型这条结果对应的是刚才哪一次工具调用。第三个是loop state，建议不要只用一堆零散局部变量，最小也应该显式收拢出一个循环状态，里面包含messages、turn_count和transition_reason。
 
最小实现五步法
Agent 循环的核心实现流程。光说不练假把式，现在来看最小实现的5个步骤：第一步准备初始消息，把用户的请求放进message数组；第2步调用模型，system prompt和工具定义一起发给模型；第3步追加system回复，这一步非常重要，很多初学者只关心最后有没有答案，忽略把system回复本身写回历史，下一轮上下文就会断掉；第4步如果模型调用了工具，就执行工具并把结果包装成tool_result，带上tool_use_id；第5步把工具结果作为新消息写回去，然后下一轮重新发给模型。
 
Agent Loop 最小核心
全部代码不超过 30 行，涵盖核心原理。整个agent loop在while true循环里：首先调用模型，然后把assistant的回复追加到messages，接着检查stop reason，如果不是tool_use就直接return，否则遍历response content中的tool_use块，执行工具并收集结果，最后把结果作为user消息写回messages，turn_count加一，transition_reason设为tool_result，然后继续下一轮。这就是最小agent loop，全部代码不超过30行，但已经涵盖了核心原理。
 
Agent 循环扩展机制
所有章节在做同一件事：往循环里增加新能力。从现在开始，后面所有章节本质上都在做同一件事：往这个循环里增加新的状态、新的分支判断和新的执行能力。比如S02往里面接工具路由，S03往里面接规划状态，S06往里面接上下文压缩，S07往里面接全栈判断，S11往里面接错误恢复。所以请把这一章牢牢记成一句话：agent的核心不是模型很聪明，而是系统持续把现实结果喂回模型。模型再强，没有这个循环就只是空想。
 
初学者五大错误
Claude Code Agent 循环·避坑指南。最后说几个初学者最容易犯的错误：第一个，把工具结果打印出来，但不写回messages，模型下一轮根本看不到真实执行结果；第二个，只保存用户消息，不保存assistant的消息，这样上下文会断层，模型会越来越不像；第三个，不给工具结果绑定tool_use_id，模型会分不清哪条结果对应哪次调用；第四个，一上来就把流式、并发、恢复、压缩全塞进来，这会让主线变得非常难学，先把最小回路打起来，不要急于求成；第五个，以为messages只是聊天展示，不是的，在agent里，messages是下一轮工作输入。
 
核心记忆
Agent Loop 的本质：动作意图 → 执行结果 → 继续推理
messages → model → tool_result → next turn
Agent 之所以从“会说”变成“会做”，是因为模型输出能走到工具，工具结果又能回到下一轮模型输入。今天的核心记住：agent的本质是把模型的动作意图变成真实执行结果，再把结果送回模型继续推理。agent之所以从会说变成会做，是因为模型输出能走到工具，工具结果又能回到下一轮模型输入。写出message→model→tool_result→next turn这条回路，今天的内容你就掌握了。
